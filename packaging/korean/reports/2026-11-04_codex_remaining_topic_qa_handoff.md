## 0. Codex에 전달할 최상위 지시

**끝까지 진행할 것.** 일부분만 자동 검색하여 "전수 완료"라고 보고하지 말 것. 이미 완료한 원본 대응/수정/테스트를 불필요하게 반복하지 말고, 먼저 산출물과 소스 SHA를 재검증해 베이스라인을 확정할 것.

1. 네이티브 무손실 후보 1,378개 중 **이미 수동 검수한 우선 367개를 제외한 1,011개(662+349)의 영문 전문↔한국어 전문 개별 의미 검수**를 수행한다. 실제로 오류라고 확정된 개수가 아니라 미검수 후보 수이다. 동일 원문·번역·토픽·조건은 SHA 기반으로 중복을 묶되, **물리 INFO별 원본 ID·원문·조건의 차이를 보존**하고 verdict를 다시 모든 INFO에 연결한다.
2. **기존 정상 링크를 가리는 285개 위험 후보**는 수정 가능 목록이 **아니다**. 현재 잘 작동하는 긴 토픽/한국어 문장과 짧은 새 명시 태그의 충돌 원인을 상세히 조사하고, 손실 0을 입증하는 해법이 있는 경우에만 별도 승인 대상으로 올린다. 해결책이 없으면 **안전 보류**하고 원문 유지.
3. 전체 누락 후보가 이 1,011+285건으로 끝나는 것이 **아니다**. 17개 모드/변형의 **6,249개 모드×토픽 고유 검토 묶음**을 범위로 삼아 의역·명칭 불일치·조건부 NPC 대화·모드 간 링크 우선순위도 함께 검토하고 남은 의미 미확인 부분을 추적한다. 불필요·비클릭성 일상어/저널 전용/재현되지 않는 후보는 명시적으로 제외 근거를 작성한다.
4. **제국교단 가입** 등 고위험 퀘스트는 실제 NPC 상태/퀘스트/스크립트 조건 및 선택지 연결을 재현할 것. 구조적 토픽 연결 정상 판정만으로 게임 내 가입 완료·승진 완료를 선언하지 말 것.
5. 검증된 개별 수정은 **별도의 후보/시험 빌드에만** 적용하여 바이너리/스크립트/로드 순서/12개 구성 회귀를 모두 검사한다. **사용자 설치 게임·세이브·기존 공개 파일·다른 저장소를 건드리지 말 것.** GitHub/Nexus 새 릴리스 업로드는 후보의 검증 결과를 보고하여 사용자 지시를 받은 뒤 진행한다. 버전은 사용자 정책대로 숫자를 올리고 **rc, RC1, pre 접미사 사용 금지**.

## 4. 실제로 할 작업 순서 (완료 기준 포함)

### A. 현행 공개판을 불변 베이스라인으로 고정
1. Git/GitHub 상태, 실제 Nexus/GitHub 버전, 각 ZIP 및 플러그인별 SHA, 원본 영문 플러그인 버전/의존성을 수집하고 \`baseline_manifest.json\` 작성.
2. **KR12.8 · kr0.2 · Rebirth kr1.2**와 그에 대응하는 원본 영어 ESM/ESP에서 INFO.INAM/물리 순서/영문 DIAL/조건/텍스트/TOP/MRK/JRN 고정.
3. 기존 353건 수정은 이미 해결된 항목으로 목록화. 해당 INFO를 새 누락으로 재제안하면 중복/역행 오류다.

### B. 1,011개 안전 후보의 전수 의미 검수
1. 원문 전문·한국어 전문과 함께, 실제 대상 \`DIAL\`, 소스 영문 토픽 ID, 한국어 DIAL명, NPC/퀘스트 맥락, 접미 조사, 기존 자동/명시 링크, 현재 TOP/MRK 우선순위를 펼친 검사 자료 생성.
2. 662와 349를 각각 **전수** 순회. 고유 중복은 효율적으로 합치되 빠진 INFO가 없도록 **원본 물리 인덱스별 상태판정 1,011/1,011**. 모든 row에 \`PASS_NO_CHANGE\`, \`PROPOSE_SAFE_LINK\`, \`FIX_TRANSLATION\`, \`HOLD_CONTEXT\`, \`NOT_A_LINK\` 같은 명시 verdict + 한국어 근거 기록.
3. 영어 원문과 한국어 문장이 서로 다른 방식으로 의역된 경우 문자 일치로 결론 내리지 말고 **화자·대화 주제·맥락·토픽 의도**로 검증한다. 길드 가입, 인명/지명, 퀘스트 단서·아이템 우선.
4. \`PASS\`와 \`NOT_A_LINK\`도 검사 완료에 포함하되 **'고침'으로 집계하지 말 것**. HOLD는 이유 및 게임 내 확인 방법이 있어야 함.

### C. 285개 위험 및 광역 6,249개 의미 미확인 감사
1. 기존 **긴 토픽 보존** 기준으로 285건 각각 관련 원문·한국어·기존 클릭 링크·새 태그가 가리는 대상을 정리. **신규 태그만으로 복원 금지**. 마스킹 위험 해법이 없으면 HOLD.
2. 모드×토픽 **6,249개** 전체의 중복/진행률 매니페스트 생성. 1,011/285/기존 353과의 **교집합** 표시. 2,127 의역/검색어 불일치, 2,931 문맥/매핑 불명 등 **어려운 유형도 남김없이 판정**. 710 저널 전용 항목은 \`.jrn\`/저널 조건 검증으로 분리.
3. 전체 감사의 목표는 **실제로 클릭해야 하는 토픽이 누락된 부분만 고치는 것**이며, 일상어·호칭·NPC 고유명사가 언급되기만 한 모든 사례에 링크를 달지 않는다.
4. 원본과 번역의 수치/조건/변수 차이, 멀티모드 로드 순서, \`AddTopic\`/\`Choice\`/\`Journal\` 연결 차이는 별도 오류 판정·재현 파일로 보관한다.

### D. 검증된 최소 바이너리 수정·실제 플레이테스트
1. **원본·현재 공개판 쓰기 금지.** 버전별 별도 산출물 디렉터리에서만 새 ESP/ESM/TOP 파일을 만든다. INFO.NAME 중심 최소 수정. \`INAM\`, \`DIAL\`, \`SCVR\`, \`BNAM\`, \`FLTV\`, \`INTV\`, \`Choice\`/Journal 스크립트/조건, 레코드 순서/헤더/다른 필드, 기타 파일은 **명시적으로 검증된 예외가 없으면 변경 금지**.
2. \`@한글 명칭#\`만 적는다고 반드시 원문 토픽에 연결되는 게 아님. 필요한 경우 한국어 표시 문자열의 명시 태그/패딩과 \`.top\` 별칭을 **실제 영문 DIAL ID**로 연결. \`.mrk\`는 **한국어 DIAL명을 검색 키로 쓰는 구조**를 확인. 기존 TOP/MRK 매핑을 덮어쓰거나 기존 긴 토픽을 짧은 태그로 가리지 않는다.
3. Python/TES3 필드 바이트·SHA 검증 + 독립 \`esmtool -q -C dump\` + OpenMW 0.51 네이티브 \`KeywordSearch\` 실행. 12개 동일 로드 구성에서 **전체 INFO**의 이전 링크 손실 0, 미수정 INFO 의도치 않은 신규 링크 0, 승인 토픽 타깃 누락 0, 표시 문장 불일치 0. 원본과 새로운 후보 전용 검사 두 개를 분리해 비교.
4. 최소 실게임 확인: **제국 교단 가입→실제 가입 완료**, 전사 길드/마법사 길드/텔바니 가입, 승진, 퀘스트 일지·분기·선택지, NPC 인사말, 복수 플러그인 로드 구성. 별도 테스트 세이브/완전한 지역 모드 리소스를 사용하고 기존 세이브는 건드리지 않는다. 불가능한 부분은 \`NOT_PLAYTESTED\` 표시.
5. 원본 자체의 PFP \`Goobye\` / TR \`Kha'Raji\` 컴파일 오류와 격리 환경 지역 리소스 누락 경고는 **기존 기준선**. 새 후보로 인한 신규 오류와 분리 보고하고 임의로 원본 스크립트 문제를 새 한글 패치의 성과로 기록하지 말 것.

## 5. 사용자 요청에서 중요한 운영 규칙

- 소방/다른 프로젝트와 무관하게 **현재 모로윈드 번역의 정확성·플레이 호환성 최우선**.
- PFP와 Rebirth도 검수 범위에 포함. 단, **PFP 공개판 자체를 함부로 번역 변경하지 말 것**; 이 작업은 연결·호환 회귀를 우선 검증.

- 성공/실패 보고에 테스트 횟수와 물리 INFO 수정 건수, 고유 대사 수정 건수, **확정 링크 오류 수**를 분리해서 쓴다.

- 사용자 PC가 연결되지 않으면 진행 가능한 GitHub/원본·문맥 QA를 우선 수행하고, 외부 저장소/릴리스/사용자 원본 데이터에 대해 근거 없는 수정 완료 주장을 하지 않는다.
